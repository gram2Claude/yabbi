# Сценарий: источник БЕЗ API — статистика из личного кабинета (cookie + методы в URL)

Дополнение к шаблонной системе (перенесена из avito). Покрывает класс источников, у которых
**нет публичного API**, а статистика доступна из веб-кабинета: логин по форме → cookie-сессия →
запросы к «методам», передаваемым в параметрах URL. Эталон реализации — этот проект (`yabbi_automate`).

Добавляет к базовым вариантам шаблона (`[OAUTH]` / `[API KEY]` / `[ASYNC]` / `[SYNC]`) новый блок
**`[COOKIE SESSION]`** и паттерн эндпоинта **`[CABINET URL METHODS]`**.

---

## 1. Авторизация — `[COOKIE SESSION]`

Вместо OAuth/API-ключа:
- Вход — `POST {LOGIN_PATH}` с полями формы `{LOGIN_FIELD}` / `{PASSWORD_FIELD}`
  (`application/x-www-form-urlencoded`).
- ⚠️ Кабинеты часто требуют заголовки **`Referer`** и **`Origin`** (антибот) — без них логин
  отклоняется как неверные креды. Проверить на живом входе.
- Успех = редирект в кабинет + установка session-cookie; клиент хранит `requests.Session`.
- Сессия живёт ограниченно (часто ~1 ч), продлевается запросами → клиент **перелогинивается сам**
  по TTL и по признаку потери доступа (напр. тело `{"err": "no access"}`).
- Капча/2FA — стоп-фактор автологина: если есть, перейти на ручную cookie (пользователь копирует
  cookie из браузера в `.env`).

## 2. Эндпоинты — `[CABINET URL METHODS]`

- «Метод» кабинета — в query (`?method=…`) или в пути (`/statistics/<method>/…`).
- Ответ — JSON (нередко `Content-Type: text/plain`). **Пустой период** может приходить как `null`
  (не `[]`) или `{}` — обрабатывать как «нет данных».
- Даты — уточнить единицу (часто **Unix-мс**) и **инклюзивность `endTime`** (у Yabbi `endTime`
  ВКЛЮЧАЕТ свой день; нулевой диапазон `startTime==endTime` может отвергаться `400`).
- **gzip:** запрашивать `Accept-Encoding: gzip` — не только экономия, но и обход сетевых затыков
  на больших ответах (на некоторых сетях ответы >~16 КБ «висят» без сжатия). `requests` шлёт и
  распаковывает автоматически; при ручном `urllib` — распаковывать самому.
- **Забор по дням:** тяжёлые/крупные выгрузки тянуть по 1 дню за запрос (и чтобы держать ответ малым).

## 3. Кумулятивные метрики (охват) — как в avito `[CUMULATIVE]`

Охват/уники **неаддитивны** → не суммировать по дням. Значение за день D берётся запросом за период
`[global_start_date, D]`; дневной прирост `increment[D] = reach[D] − reach[D−1]`. `global_start_date`
хранится в `.env`. Полностью совпадает с блоком `[CUMULATIVE]` шаблона ТЗ (`tz_templates/10_template_tz.md`).

## 4. Что заполнить в анкете (дополнение к `02_NEW_PROJECT_QUESTIONNAIRE.md`)

- B1 тип авторизации = `cookie session`; поля формы; нужны ли `Referer`/`Origin`.
- B2 базовый URL кабинета; B3 паттерн «метод в URL»; B4 единица дат + инклюзивность `endTime`.
- B6 gzip; B7 забор по дням; B8 кумулятивные метрики (если есть).

## 5. Отличие обогащения DataFrame

Сквозное avito-обогащение (`account_id`/`source_type_id`/`id_key_*`, `costs_nds`/НДС/`ak`) —
**НЕ обязательно**. Набор колонок задаётся явно под проект (в `yabbi_automate` — минимальные таблицы;
деньги `budget` уже десятичные, НДС-логика не применяется).

## 6. Клиент — что меняется в `04_template_client.py`

- Убрать блоки `[OAUTH]`/`[API KEY]`; добавить `[COOKIE SESSION]`: `_do_login()` (форма + Referer/Origin),
  `_ensure_session()` (TTL/перелогин), `requests.Session`.
- `_get_json()` — с `Accept-Encoding: gzip`, ретраями и детектом `{"err": …}` → перелогин.
- Убрать submit/poll/download (`[ASYNC]`); эндпоинты синхронные, «метод» — в URL.
- Кумулятивную функцию оставить (`[CUMULATIVE]`), запрос за `[global_start_date, D]`.

Готовый образец всего перечисленного — `yabbi_automate/yabbi_automate.py`.
